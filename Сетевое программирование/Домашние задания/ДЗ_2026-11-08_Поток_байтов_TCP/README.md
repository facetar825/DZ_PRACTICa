## Вопросы для самопроверки

1. TCP передаёт непрерывную последовательность байтов. Данные нескольких записей могут объединиться или разбиться.
2. Строка JavaScript представлена кодовыми единицами UTF-16, а последовательность байтов зависит от выбранной кодировки.
3. `Buffer.from()` создаёт буфер, например кодируя строку в UTF-8.
4. `'Я'.length` равна 1 кодовой единице UTF-16. `Buffer.byteLength('Я')` равна 2 байтам UTF-8.
5. Декодирует UTF-8 потоково и сохраняет многобайтовый символ, если тот разделён между фрагментами.
6. Потому что в одной порции могут быть несколько законченных строк.
7. Экранировать переводы строк или перейти на фреймирование по длине.
8. Это число байтов тела после заголовка. Например, его можно представить четырьмя байтами big-endian.
9. Чтобы один клиент не мог бесконечно наращивать буфер незавершённого сообщения или заставить сервер выделить слишком много памяти.
10. Это ограничение темпа отправки по готовности потребителя. После `write() === false` перед дальнейшей интенсивной отправкой ожидают `drain`.
