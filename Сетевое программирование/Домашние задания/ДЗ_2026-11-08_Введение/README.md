# Клиент, сервер, IP-адреса и порты

## Вопросы мини-практики

1. Клиент начинает обмен, сервер ожидает и обслуживает входящие запросы.
2. Да. Отдельные процессы могут общаться через loopback на одном ПК.
3. На одном IP может быть несколько сервисов. Порт указывает, к какому из них направить запрос.
4. Запрос пойдёт по сети к соседнему компьютеру. Сервер должен слушать на его сетевом интерфейсе, а порт должен быть доступен по сети.
5. Ping проверяет ICMP-ответ. Доступность TCP на порту 3000 нужно проверять отдельным подключением.

## Вопросы для самопроверки

1. Сетевое взаимодействие — обмен данными между программами через сетевые интерфейсы и протоколы.
2. IP адресует интерфейс, а порт выбирает транспортную точку сервиса.
3. DNS позволяет находить сетевые записи по доменным именам.
4. Привязка к `127.0.0.1` принимает только локальные соединения. Привязка к `0.0.0.0` принимает соединения на доступных IPv4-интерфейсах.
5. TCP упорядочивает поток и восстанавливает потерянные данные, а UDP отправляет отдельные датаграммы без этих гарантий.
6. Границы записей не передаются. Клиент и сервер сами определяют, где заканчивается сообщение.
7. HTTP задаёт структуру запросов и ответов. TCP, например при HTTP/1.1, переносит байты этих сообщений.
8. `node:net` для TCP, `node:dgram` для UDP, `node:http` для HTTP.
9. `EADDRINUSE` означает, что указанный адрес и порт уже используются.
10. `ipconfig` показывает адреса интерфейсов, `ping` проверяет ICMP, `nslookup` проверяет DNS. Для списка сокетов дополнительно используют `netstat -ano`.
