# Жизненный цикл TCP-соединения

[Конспект](<../../Конспекты/тема_02_Жизненный_цикл_TCP/README.md>) · [Практика и результаты](<../../Лабораторные и Практические работы/ПР_02_NetLab_TCP/README.md>)

## Вопросы для самопроверки

1. TCP-соединение установлено, сокет готов к обмену данными.
2. Объект одной стороны конкретного TCP-соединения.
3. `data` обозначает порцию потока. Команда определяется приложением и может занимать несколько порций.
4. `end` завершает входящую передачу, `close` означает освобождение ресурса сокета.
5. `end()` штатно заканчивает запись, `destroy()` немедленно прекращает обмен.
6. Настраивает обнаружение бездействия. Событие `timeout` само по себе не закрывает сокет.
7. При попытке слушать занятый адрес и порт возникает `EADDRINUSE`. Занятый порт можно найти в `netstat -ano`.
8. У сервера отдельно обрабатывают ошибки прослушивания, у каждого сокета — сброс, отказ в подключении и другие ошибки обмена.
9. TCP-подключение подтверждает готовность транспортного канала. Выполнение команды подтверждается ответом приложения.
10. Остальные сеансы продолжаются: каждый клиент имеет свой сокет, а прослушивающий сервер остаётся активным.
