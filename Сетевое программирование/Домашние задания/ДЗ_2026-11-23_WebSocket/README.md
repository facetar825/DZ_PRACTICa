# WebSocket и обмен в реальном времени

[Конспект](<../../Конспекты/тема_08_WebSocket/README.md>) · [Практика](<../../Лабораторные и Практические работы/ПР_08_WebSocket/README.md>)

## Ответы на вопросы для самопроверки

1. Для постоянных двусторонних обновлений, например в чате или системе уведомлений.
2. Polling периодически повторяет запросы. WebSocket позволяет отправлять сообщения по уже открытому каналу.
3. Upgrade согласует переход с HTTP/1.1 на WebSocket.
4. 101 Switching Protocols подтверждает смену протокола в классическом рукопожатии.
5. wss защищает соединение через TLS, ws передаёт данные без этой защиты.
6. send передаёт текстовое или двоичное сообщение по открытому WebSocket.
7. 0 CONNECTING, 1 OPEN, 2 CLOSING, 3 CLOSED.
8. TCP data доставляет произвольный фрагмент потока. WebSocket message содержит собранное сообщение.
9. WebSocket определяет доставку и фреймирование. Содержимое может быть текстом или двоичными данными в формате приложения.
10. Ping/Pong — управляющие фреймы протокола. Прикладная команда является обычным содержимым сообщения.
11. Чтобы ограничивать расход памяти и отклонять неожиданный формат или недопустимые значения.
12. close нужен для очистки состояния клиента, error — для регистрации сбоев. При штатном завершении стороны обмениваются Close-фреймами.
