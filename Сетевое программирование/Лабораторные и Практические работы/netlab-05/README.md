# Практическая работа №5 — устойчивый многоклиентский TCP-сервер NetLab

## Запуск

Откройте папку `netlab-05` в VS Code/PowerShell. В первом терминале:

```powershell
node server.mjs
```

В двух (или более) других терминалах:

```powershell
node client.mjs
```

Сервер работает на `127.0.0.1:3020`. Требуется только Node.js; `npm install` не нужен.

## Команды клиента

- `PING` → `PONG`
- `SAY Привет!` → `SENT` отправителю, остальные клиенты увидят `[user-N] Привет!`
- `STATS` → число текущих подключений и команд этого клиента
- `WHO` → ID и исходящие порты всех активных клиентов
- `HELP` → доступные команды
- `IDLE` → время бездействия (20 секунд по умолчанию)
- `QUIT` → `BYE` и завершение соединения
- Неизвестная команда → `ERROR UNKNOWN_COMMAND` без отключения

## Самостоятельная часть и повышенная сложность

Включены `WHO`, `HELP`, `IDLE`, время `[CONNECT]`/`[CLOSE]`, увеличенный до **5** лимит клиентов и асинхронное предупреждение `WARNING IDLE` примерно за 5 секунд до штатного отключения на 20-й секунде бездействия.

Для проверки лимита подключите **пять клиентов**, а затем откройте шестого: он получит `ERROR SERVER_FULL`. Исходное упражнение про четвёртого клиента относится к первоначальному лимиту 3, до самостоятельной доработки.

Размер каждой строки — до 1024 байт UTF-8; бо́льшие сообщения завершаются `ERROR LINE_TOO_LONG`. Повреждение или отключение одного клиента не останавливает остальные соединения. Команды извлекаются из TCP-потока по символу `\n`; проверка байтов сделана до декодирования UTF-8.

## Тесты

```powershell
node tests/smoke.mjs
```

18 проверок. Тест временно устанавливает `NETLAB_IDLE_MS=1400` для ускоренного сценария предупреждения и тайм-аута; **обычный запуск** работает с `IDLE_MS=20000` (20 секунд). Вне теста эту переменную среды задавать не нужно.

## Быстрая демонстрация преподавателю

1. Запустить сервер и два клиента.
2. Выполнить `PING`, `SAY Тест`, `STATS`, `WHO`, `HELP`, `IDLE`.
3. Выполнить неверную команду и затем `PING` — соединение сохраняется.
4. Завершить одного клиента через `QUIT` — второй продолжит отвечать.
5. Подключить пять клиентов, шестому показать `ERROR SERVER_FULL`.
6. Оставить клиент без команд: сначала `WARNING IDLE`, затем `ERROR IDLE_TIMEOUT`.
7. Открыть PDF-отчёт из папки `отчёт/` и объяснить независимое состояние клиентов в `Map`.
