# Практическая работа №6 — Unicast, Broadcast и Multicast в UDP

## Подготовка и запуск

Требуется Node.js, дополнительных пакетов нет. В папке `netlab-06`:

**Терминал 1 — приёмник:**

```powershell
node receiver.mjs
```

**Терминал 2 — отправитель Unicast:**

```powershell
node sender.mjs unicast 127.0.0.1 "Объявление для одного ПК"
```

**Broadcast (используйте настоящий broadcast-адрес вашей разрешённой локальной подсети):**

```powershell
ipconfig
node sender.mjs broadcast 192.168.1.255 "Объявление всему сегменту"
```

`192.168.1.255` — пример **только для** подсети `192.168.1.0/24`. Адрес широковещательной рассылки зависит от маски и может быть другим. Для преподавателя используйте реальные IP и маску собственных учебных ПК.

**Multicast (основная группа):**

```powershell
node sender.mjs multicast 239.255.10.10 "Объявление группе 1"
```

**Вторая multicast-группа:**

По умолчанию приёмник подписан только на первую группу. Перезапустите его с подпиской на вторую:

```powershell
$env:MULTICAST_GROUPS = "239.255.10.11"
node receiver.mjs
```

В другом терминале:

```powershell
node sender.mjs multicast 239.255.10.11 "Объявление группе 2"
```

Для одновременной подписки на две группы: `$env:MULTICAST_GROUPS = "239.255.10.10,239.255.10.11"`.
Для отмены переменной в PowerShell: `Remove-Item Env:MULTICAST_GROUPS` (если она установлена).

Когда у компьютера несколько интерфейсов, можно явно выбрать собственный IPv4 интерфейса в терминале **каждой** машины:

```powershell
$env:MULTICAST_IFACE = "192.168.1.10"
node receiver.mjs
```

Число `192.168.1.10` — пример, используйте действительный локальный IPv4 нужного интерфейса. Для отправителя переменная задаётся на компьютере отправителя со **своим** IPv4.

**Для остановки приёмника** напечатайте `STOP` в его собственном терминале. UDP-сообщение с текстом `STOP` не выключит приёмник.

## Тесты

```powershell
node tests/smoke.mjs
```

16 успешных локальных проверок на Node.js v22.16.0. Проверены Unicast на 127.0.0.1, дата/время, локальная команда STOP, передача Broadcast в `127.255.255.255` через loopback, подписки на обе multicast-группы. Этот результат **не гарантирует** приём Broadcast/Multicast в сети кабинета. UDP в принципе не гарантирует доставку.

## Безопасность и вывод

Тестируйте Broadcast/Multicast только в собственной/разрешённой учебной сети. Изменение правил брандмауэра и эксперименты с другими сетевыми устройствами требуют согласования. Если Multicast заблокирован сетью, зафиксируйте реальное отсутствие доставки, а не подменяйте результат.
