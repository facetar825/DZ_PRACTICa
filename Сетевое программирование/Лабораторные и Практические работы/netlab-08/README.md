# Практическая работа №8 HTTP-клиент NetLab

Сначала запусти сервер из ../netlab-07: node server.mjs. Затем в этой папке:

```powershell
node client.mjs
node client.mjs status
node client.mjs events
node client.mjs send PC-07 "Нужна помощь"
node client.mjs slow 1000
node client.mjs slow 4000
```

Без аргументов запускается демонстрация GET/POST, 400, 404, 405, 503 и двух тайм-аутов. Функции getStatus, createEvent и getEvents экспортируются для повторного использования. request выводит статус, ok, Content-Type, Cache-Control, тело и время полного чтения ответа.

getStatus повторяет запрос один раз через 250 мс, если полный HTTP-ответ не получен. HTTP 4xx/5xx не повторяются. POST автоматически не повторяется. При отказе подключения печатаются ECONNREFUSED и подсказка запуска сервера.

## Результаты

Автоматическая проверка получила 201 при POST, созданное событие при GET и ok=false для 404/503. При тайм-ауте 1000 мс запрос на трёхсекундный маршрут прервался примерно через 1009 мс. При 4000 мс ответ 200 пришёл примерно через 3005 мс. После остановки сервера обе попытки getStatus вернули обработанный ECONNREFUSED.

## Ответы на вопросы

1. fetch возвращает Response при получении HTTP-ответа.
2. Числовой код находится в response.status.
3. response.ok равен true для 200–299.
4. HTTP 404 — полученный ответ, поэтому fetch обычно разрешает Promise с ok=false.
5. Тайм-аут прерывает ожидание. 503 — полученный статус временной недоступности.
6. AbortSignal.timeout ограничивает ожидание запроса и чтения тела.
7. Нужно задать POST, Content-Type application/json и тело JSON.stringify(data).
8. text читает строку. json читает тело и разбирает JSON, при ошибочном JSON выбрасывает исключение. Тело обычно читают один раз.
9. Заголовки описывают формат, кеширование и другие свойства ответа. no-store просит не сохранять ответ в кеше.
10. Повтор POST может создать дубликат. Для безопасных повторов операций записи нужен отдельный механизм идемпотентности.
