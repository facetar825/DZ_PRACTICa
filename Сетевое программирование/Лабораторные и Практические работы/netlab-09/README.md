# Практическая работа №9 Многоклиентский WebSocket-чат NetLab

Требуется Node.js 22+. В этой папке выполни:

```powershell
pnpm install --frozen-lockfile
node server.mjs
```

При установленном npm также работает npm install. Открой http://127.0.0.1:3060/ в трёх вкладках, используй разные имена. Сообщения доставляются всем вошедшим участникам. При отключении одного остальные продолжают обмен.

## Самостоятельные доработки

- WELCOME отправляется только новому участнику после принятия имени.
- Сервер считает успешные общие и личные сообщения. /who, join и ошибки в счётчик не входят.
- Участники отображаются вместе со временем подключения.
- /who в поле сообщения возвращает список только отправителю. В JSON доступен type: "who".
- Каждый сокет может отправить не более пяти команд за скользящие десять секунд, включая join и ошибочные команды. Превышение возвращает RATE_LIMIT. Отклонённые по лимиту команды окно не продлевают.
- Личное сообщение отправляется по имени из поля получателя. При отсутствии адресата возвращается USER_NOT_FOUND, при успехе текст видят отправитель и получатель.

Имена содержат 1–20 символов, общий или личный текст — 1–200 символов после trim. Допускается максимум 20 соединений. Пакет ограничен 2048 байтами, данные бинарного типа отклоняются. При неверном join интерфейс закрывает сеанс и позволяет подключиться снова.

## Проверки

node tests/smoke.mjs запускает общую проверку работ №7–9 и останавливает созданные процессы. Порты 3041 и 3060 должны быть свободны.

Проверены три одновременных подключения, WELCOME, список онлайн, рассылка, /who, приватность личных сообщений, выход с кодом 1000 и дальнейшая работа остальных участников. Проверены NAME_TAKEN, INVALID_JSON, UNKNOWN_TYPE, INVALID_TEXT, RATE_LIMIT и закрытие слишком большого сообщения с кодом 1009. Пользовательский текст выводится через textContent.

Для ручной диагностики в браузере открой DevTools → Network → WS, выбери /ws и посмотри 101 Switching Protocols и сообщения JSON. Отключись кнопкой и сопоставь close с записью [CLOSE] в сервере. Проверку вкладок и DevTools в этой сессии вручную не проводили.

## Ответы на вопросы

1. fetch создаёт HTTP-запрос с ответом. WebSocket сохраняет двусторонний канал для сообщений.
2. Upgrade согласует переход с HTTP/1.1 на WebSocket.
3. Код 101 подтверждает переход протокола.
4. WebSocketServer выполняет рукопожатие и обрабатывает WebSocket-фреймы.
5. Map хранит сокет, имя и состояние каждого клиента для рассылки и очистки.
6. readyState показывает, можно ли отправлять данные.
7. Сервер отправляет сообщения по существующим соединениям без новых GET.
8. close удаляет сокет из Map и обновляет уведомления и список.
9. Входной JSON может быть некорректным или содержать неподдерживаемые значения.
10. maxPayload ограничивает размер сообщения и расход памяти.
11. textContent отображает введённую HTML-разметку буквально.
12. Для публикации потребуются TLS, аутентификация, проверка прав и Origin, защита от злоупотреблений. Учебный сервер слушает loopback.
