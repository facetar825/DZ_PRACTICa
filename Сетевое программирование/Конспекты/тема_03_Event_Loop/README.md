# Асинхронность и Event Loop

Синхронный код удерживает основной поток JavaScript до завершения операции. Неблокирующий ввод-вывод позволяет продолжить другую работу, пока данные недоступны. Node.js использует libuv и механизмы ОС для обработки сетевых операций.

Event Loop запускает обработчики готовых событий, включая события сокетов и таймеры. Микрозадачи Promise выполняются после текущего синхронного кода на контрольных точках, поэтому в демонстрации `Promise.then()` предшествует таймеру с нулевой задержкой. Таймер задаёт минимальную задержку до возможности выполнения.

Callback вызывается при готовности результата. Promise хранит состояние и будущий результат или ошибку. `await` приостанавливает текущую async-функцию до разрешения Promise, поэтому основной поток может обрабатывать другие события. Тяжёлый синхронный код в этой же функции всё равно блокирует поток.

Несколько TCP-сокетов могут ожидать I/O одновременно. Обработчики JavaScript в основном потоке выполняются последовательно. Если `socket.write()` возвращает `false`, очередь записи достигла порога. Нужно снизить темп отправки и дождаться `drain`.

[Документация Node.js по TCP-сокетам](https://nodejs.org/api/net.html).
