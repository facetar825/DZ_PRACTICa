# Прикладные протоколы HTTP, SMTP и FTP

Прикладной протокол задаёт структуру сообщений и их смысл. TCP доставляет поток байтов, а HTTP определяет методы, ресурсы, заголовки, тело и коды ответа. URL содержит схему, хост, необязательный порт, путь и параметры запроса.

HTTP/1.1-запрос начинается с метода, пути и версии. Затем идут заголовки, пустая строка и необязательное тело. Ответ содержит версию, статус, заголовки и тело. Заголовки разделяются CRLF. Content-Type определяет формат тела, Content-Length выражает длину в байтах.

GET получает представление, HEAD возвращает заголовки, POST передаёт данные для обработки, PUT создаёт или полностью заменяет представление, PATCH изменяет его частично, DELETE запрашивает удаление. Safe-методы предназначены для чтения. Идемпотентный метод имеет одинаковый предполагаемый эффект при однократном и повторном одинаковом запросе.

200 означает успех, 201 — создание ресурса, 204 — успех без тела. 400 сообщает об ошибке запроса, 404 — об отсутствии ресурса, 405 — о неподдерживаемом методе. 413 означает превышение размера тела, 415 — неподдерживаемый формат, 500 и 503 относятся к ошибкам сервера.

Несколько HTTP-запросов могут использовать одно TCP-соединение. HTTP/2 поддерживает мультиплексирование, HTTP/3 использует QUIC поверх UDP. HTTP stateless позволяет приложению хранить сессии, передавая их идентификаторы в запросах. HTTPS защищает канал с помощью TLS.

SMTP предназначен для отправки и пересылки почты. Чтение почты выполняют через IMAP или POP3. FTP использует управляющий и отдельный канал передачи данных. FTPS применяет TLS к FTP, SFTP представляет отдельный протокол поверх SSH.
