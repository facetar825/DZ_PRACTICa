# Клиент, сервер, IP-адреса и порты

Сетевые приложения передают данные через согласованные протоколы. Клиент инициирует запрос, сервер слушает адрес и порт. На одной машине обе роли могут выполнять разные процессы.

IP-адрес определяет сетевой интерфейс, а порт помогает выбрать приложение. `127.0.0.1` адресует тот же компьютер. Частный IPv4 может использоваться для связи по локальной сети. Привязка сервера к `0.0.0.0` означает прослушивание всех локальных IPv4-интерфейсов. Клиент подключается к конкретному адресу.

DNS возвращает записи, например A для IPv4 и AAAA для IPv6. Успех DNS-запроса или ICMP-проверки через `ping` ничего сам по себе не говорит о доступности конкретного TCP-порта.

TCP предоставляет надёжный упорядоченный поток байтов, UDP передаёт самостоятельные датаграммы без гарантии доставки или порядка. HTTP задаёт смысл запросов и ответов. WebSocket позволяет обеим сторонам отправлять сообщения по длительному соединению.

Для учебных приложений Node.js предоставляет `node:net`, `node:dgram`, `node:http`. На Windows первичная диагностика: `ipconfig`, `ping`, `nslookup`, `netstat -ano`.

[Документация Node.js по TCP-сокетам](https://nodejs.org/api/net.html).
