# TCP как поток байтов

TCP сохраняет порядок байтов, но не отмечает границы вызовов `write()`. Получатель обязан определить границы сообщений по правилам протокола.

`Buffer` хранит байты. UTF-8 кодирует символы последовательностями переменной длины, поэтому декодирование каждого произвольного фрагмента независимо может испортить символ. Решение: потоковое декодирование через `socket.setEncoding('utf8')` или накопление байтов до полной строки.

В строковом протоколе каждый LF заканчивает кадр. Нужно извлекать все строки из поступившего фрагмента, сохраняя остаток. Если перевод строки входит в содержимое, его можно экранировать или выбрать двоичный протокол с длиной.

Протокол с длиной может передавать заголовок из 4 байтов big-endian и затем указанное число байтов. Длина относится к данным, а не к числу символов. Лимит нужно проверять до выделения памяти. Для строкового протокола ограничивают и законченные строки, и накопленный остаток.

При интенсивной отправке backpressure помогает контролировать размер очереди. `write() === false` означает, что до следующей серии записей стоит дождаться события `drain`.
