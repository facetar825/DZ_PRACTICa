## Как запустить

1. Откройте SSMS и подключитесь к Microsoft SQL Server 2016 SP1 или новее.
2. Если готовая база `CollegeDB` преподавателя есть, используйте её. Нужны таблицы `college.groups`, `college.students`, `college.grades` с полями из условия.
3. Если базы нет, сначала выполните целиком `00_Учебная_база.sql`. Он создаёт демонстрационную базу, только когда `CollegeDB` отсутствует. Если база существует, он останавливает создание; существующие таблицы и данные не удаляются.
4. Откройте и выполните целиком `Mingazov_Akhnaf_sqlserver.sql`. Разделители `GO` обрабатываются SSMS.
5. Посмотрите результаты запросов и журнал аудита в разделе проверки триггера.

Присланный `college(Пара 4).sql` не подходит для восстановления именно этой лабораторной: он создаёт таблицы в `dbo`, использует `journal` вместо `grades`, другую структуру студентов и не содержит данных. Также в нём отсутствует `students.group_id` и расходятся названия `shedule` и `schedule`.

## Проверки и ожидаемые результаты

На демонстрационных данных задания 1 и итоговый запрос возвращают шесть студентов. У Павла Кузнецова нет оценок: количество равно 0, среднее по оценкам равно NULL, статус — «Нет данных».

В группе ИС-31 Ахнаф и Алексей имеют одинаковый балл 4.50 и первое место; Мария имеет третье место. Это поведение `RANK`, а не `DENSE_RANK`. При общем рейтинге Анна с баллом 4.75 занимает первое место.

Процедура с порогом 4.5 возвращает трёх студентов, с порогом 3.5 — четырёх. Скалярная функция отдельно проверяется на границах 3.49, 3.50, 4.49, 4.50 и NULL.

Первая проверка триггера добавляет одну запись аудита, вторая — ещё три. Повторное присваивание прежнего балла не добавляет записей. Тесты выполняются в транзакции и откатываются после вывода журнала, поэтому повторный запуск не накапливает прибавки к баллам. На другой базе для проверки `+0.1` должны существовать студент `id = 1` и несколько студентов `group_id = 1` с ненулевыми баллами, позволяющими прибавку без нарушения ограничений.

## Для защиты

- `JOIN` связывает таблицы; `GROUP BY` позволяет посчитать агрегаты на одного студента.
- `CTE` задаёт именованный результат, доступный следующему запросу.
- `RANK() OVER` вычисляет место; `PARTITION BY group_id` начинает рейтинг заново в каждой группе.
- Представление хранит запрос, процедура принимает параметр и выполняется через `EXEC`.
- Скалярная функция возвращает одно значение, табличная — строки и может участвовать в `FROM`.
- Триггер выполняется автоматически. `deleted` содержит старые строки, `inserted` — новые. Соединение этих множеств по `id` обрабатывает обновление нескольких студентов одной командой.
- `average_grade` из `students` — сохранённый средний балл, а `AVG(grades.grade)` — вычисляемое среднее по журналу. В этой работе они сравниваются в первом запросе; автоматическая синхронизация условием не предусмотрена.
