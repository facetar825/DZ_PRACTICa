## Что такое дамп

`CollegeDB_dump.sql` — текстовый SQL-скрипт, который создаёт базу, таблицы и заполняет их учебными данными. Это не резервная копия `.bak`: его открывают как запрос и выполняют в SSMS, а не выбирают через «Восстановить базу данных».

В базе три таблицы: `college.groups` — группы и специальности; `college.students` — студенты, возраст, сохранённый средний балл и группа; `college.grades` — отдельные оценки по предметам с датами. `group_id` связывает студента с группой, `student_id` связывает оценку со студентом. Всего в дампе 3 группы, 10 студентов и 30 оценок.

`college` — схема внутри базы: поэтому полное имя таблицы выглядит как `college.students`. SSMS — программа для работы с сервером, а SQL Server — сам сервер, где хранятся базы.

В исходном файле из Downloads есть удаление существующей `CollegeDB`. В копии здесь удаление заменено остановкой при существующей базе. Содержимое учебных таблиц сохранено. Исходный файл в Downloads не изменён.

## Запуск на твоём компьютере

На компьютере уже есть работающий локальный SQL Server и существующая `CollegeDB` с другой структурой. Используй следующие два файла: они работают с отдельной базой `CollegeDB_ComplexLab`.

1. Открой **SQL Server Management Studio (SSMS)**.
2. В окне подключения выбери тип сервера **Database Engine / Ядро СУБД**, имя сервера **localhost**, проверку подлинности **Windows Authentication / Проверка подлинности Windows**. Нажми **Connect / Подключиться**. Это параметры локального сервера, который был проверен при подготовке работы.
3. Выбери **File → Open → File / Файл → Открыть → Файл** (`Ctrl+O`) и открой `01_База_для_локального_запуска.sql` из этой папки.
4. Убедись, что текст не выделен частично, и нажми **Execute / Выполнить** (`F5`). SSMS выполнит весь файл: создаст `CollegeDB_ComplexLab`, таблицы и данные.
5. В левой панели нажми правой кнопкой на **Databases / Базы данных → Refresh / Обновить**. Раскрой `CollegeDB_ComplexLab → Tables / Таблицы`: должны появиться `college.groups`, `college.students`, `college.grades`.
6. Через `Ctrl+O` открой `02_Лабораторная_локальный_запуск.sql` и нажми `F5`. Этот файл сам выбирает базу через `USE CollegeDB_ComplexLab;`: менять выпадающий список баз вручную не обязательно.
7. Внизу появятся вкладки **Results / Результаты** и **Messages / Сообщения**. В результатах будут запросы, рейтинги, статусы и проверки аудита; в сообщениях не должно быть SQL-ошибок.

Файл создания базы запускают один раз. Для повторного просмотра результатов запускай только `02_Лабораторная_локальный_запуск.sql`. Если первый файл сообщает «База уже существует», не удаляй базу: перейди ко второму файлу, если таблицы уже созданы. После ошибки закрой вкладку создания, чтобы лабораторную выполнять в новом окне запроса.

## Как убедиться, что всё работает

Открой **New Query / Создать запрос** и выполни:

```sql
USE CollegeDB_ComplexLab;
GO
SELECT * FROM college.groups;
SELECT * FROM college.students;
SELECT * FROM college.grades;
SELECT * FROM college.StudentRating;
EXEC college.GetStudentsByMinGrade @min_grade = 4.5;
```

Первые три запроса должны показать 3, 10 и 30 строк. Представление возвращает 10 студентов; процедура с порогом 4.5 — 6 студентов. В рейтинге группы ИС-31 первое место занимает Мария Петрова с баллом 4.90.

После лабораторной таблица `college.student_changes` может быть пустой: проверки триггера выводят записи и затем откатывают тестовые изменения. Это специально сделано, чтобы каждый запуск не повышал баллы.

## Что делает лабораторная

Сначала запросы соединяют студентов, группы и оценки, вычисляют статистику и рейтинги. Представление `StudentRating` позволяет повторно получать рейтинг внутри групп. Процедура `GetStudentsByMinGrade` фильтрует студентов по заданному порогу. Функция `GetStudentStatus` возвращает статус по среднему баллу, а `GetStudentsByGroup` — строки студентов выбранной группы. Триггер автоматически пишет старый и новый балл в журнал при обновлении, обрабатывая сразу несколько студентов. Итоговый запрос объединяет рейтинг, статус и количество оценок.

Сохранённый `students.average_grade` и среднее отдельных оценок могут различаться: например, у Алексея средний балл 4.70, а по трём оценкам — примерно 4.67. Первое задание показывает оба показателя, не меняя данные.

## Запуск в DBeaver на этом компьютере

База CollegeDB_ComplexLab уже создана, все объекты лабораторной установлены. SQL Server принимает TCP-подключения только на 127.0.0.1 и ::1, порт 1433. Существующая CollegeDB сохранена.

В DBeaver подключение отображается как master (localhost:1433), использует Windows Authentication. Имя master — начальная база соединения; команда USE CollegeDB_ComplexLab в скрипте выбирает базу лабораторной.

Для повторного запуска используй 03_Мингазов_Ахнаф_DBeaver.sql. В SQL-редакторе выбери «Редактор SQL → Загрузить SQL скрипт» (Ctrl+Alt+Shift+O), укажи этот файл, затем «Выполнить SQL скрипт» (Alt+X). Базу повторно создавать не нужно.

Этот дополнительный файл выполняет каждый исходный блок GO через EXEC(N'...'), чтобы DBeaver не разрезал определения функций, процедур и триггера по внутренним точкам с запятой. Содержание запросов и серверных объектов соответствует основному решению. Исходный Mingazov_Akhnaf_sqlserver.sql предназначен для SSMS и сдачи с базой CollegeDB.
