# Практическая работа №4 — Чтение данных через SqlDataReader

Выполнил: **Мингазов Ахнаф**. Проект: **AdoNetPractice04**.

Выполнены все 8 частей и дополнительный JOIN. Меню:

1. Все товары: id, название, цена и доступность.
2. Поиск товара по ID.
3. Поиск по части названия через LIKE.
4. Клиенты: id, ФИО, телефон, email, включая NULL.
5. Заказы: ID, клиент, дата, статус.
6. Доступные товары по возрастанию цены.
7. Товары строго дороже заданной цены.
8. Поиск клиентов по части ФИО.
9. Заказы с заданным статусом.
10. Дополнительный JOIN orders и customers с выводом имени клиента.

Db.Rows использует ExecuteReader, HasRows и Read. Catalog читает значения через GetInt32, GetString, GetDecimal, GetBoolean и GetDateTime. Даты имеют формат dd.MM.yyyy HH:mm. У каждого запроса есть обработка пустого результата.

## Письменные ответы

1. SqlDataReader нужен для последовательного чтения строк результата при открытом соединении.
2. ExecuteReader получает reader; Read перемещает курсор к следующей строке и возвращает true, пока строки есть. До первого Read курсор находится перед первой строкой.
3. Тип метода должен соответствовать SQL-столбцу, индекс — порядку SELECT. Несоответствие вызывает ошибку типа или чтение другого поля.
4. IsDBNull проверяет SQL NULL перед типизированным чтением; HasRows проверяет наличие строк. Для отсутствующего телефона/email выводится «Не указан», для пустого результата — «Записи не найдены».
5. Параметры передают значения отдельно от SQL-кода, включая кавычки, Unicode и десятичные числа.

Проверка: «Кап», ID 1 и 999999, клиенты с отсутствующими полями, статус «Выдан» и несуществующий статус, цена 100000. Reader, command и connection освобождаются через using.

**Вывод:** последовательное типизированное чтение подходит для отчётов без загрузки всей таблицы в память.
