# Практическая работа №5 — Транзакции ADO.NET

Выполнил: **Мингазов Ахнаф**. Проект: **AdoNetPractice05**.

Выполнены все 8 частей и дополнительная отмена заказа:

| Пункт | Действие |
|---|---|
| 1 | Два UPDATE цен в одной SqlTransaction, проверка по одной изменённой строке, Commit |
| 2 | Принудительная ошибка после первого UPDATE и Rollback |
| 3 | Заказ с одной позицией, SCOPE_IDENTITY через ExecuteScalar |
| 4 | Заказ с двумя позициями и количествами, вывод номера и итоговой суммы |
| 5 | Ошибка после создания заголовка, до вставки позиции |
| 6 | Отмена тестового заказа: сначала позиции, затем заголовок |
| 7 | Ошибка отмены после удаления позиций, откат всей отмены |
| 8 | Просмотр существующих клиентов и товаров |
| 9 | Отчёт orders JOIN order_items |

Все ID и количества вводятся до начала транзакции. Клиент и доступные товары проверяются по базе. Цены берутся из products в той же транзакции, а не от пользователя. Все команды получают одно соединение и один объект transaction. Ошибка отката выводится отдельно. Отмена разрешена только для тестовых заказов текущего запуска; после перезапуска этот список очищается.

## Письменные ответы

1. Заказ и позиции объединяют, чтобы не оставить заголовок без полного состава при сбое.
2. Commit вызывают только после успеха всех команд и проверки ожидаемого числа строк.
3. Rollback отменяет неподтверждённые изменения всей транзакции. Счётчики IDENTITY могут сохранить пропуски.
4. ExecuteNonQuery необходимо проверять: UPDATE по отсутствующему ID возвращает 0 без SQL-ошибки, что нужно считать неуспехом.
5. Общая фиксация предотвращает частично сохранённое действие, а внешние ключи и ограничения проверяют допустимость данных.

## Демонстрация

Посмотрите ID пунктом 8. В пункте 2 измените цены товаров 1 и 2 — после ошибки цены должны остаться прежними. Проверьте успешный пункт 1 и отсутствие второго товара — первая цена должна откатиться. Пунктом 4 создайте заказ клиента 1 с товаром 1 в количестве 2 и товаром 3 в количестве 1: на исходных ценах сумма 430 рублей. Пунктом 9 проверьте обе позиции. Пунктом 7 проверьте откат отмены: позиции остаются. Пунктом 6 удалите этот же тестовый заказ успешно. Пункт 5 не должен оставлять нового заголовка.

В автоматической проверке после изменения цены товара 1 на 125 сумма двух позиций составила 440 рублей. Тестовые ошибки пунктов 2, 5, 7 ожидаемы.

**Вывод:** транзакция сохраняет составное действие целиком или откатывает его при сбое.
