## Реализация

| Пункт | Операция и методы |
|---|---|
| 1 | ShowProductsAsync: весь каталог, OpenAsync, ExecuteReaderAsync, ReadAsync |
| 2 | Только доступные товары |
| 3 | Поиск по части названия через LIKE @search |
| 4 | Количество клиентов через ExecuteScalarAsync |
| 5 | UpdateProductAvailabilityAsync: изменение доступности через ExecuteNonQueryAsync, проверка количества строк |
| 6 | GetProductCountAsync: количество товаров, Task<int>, токен отмены |
| 7 | ShowProductsFromPriceAsync: товары с ценой не меньше @min_price |
| 8 | GetCustomerOrdersAsync: заказы выбранного клиента через JOIN и @customer_id |

Все обращения к SQL Server асинхронные. Методы чтения и открытия получают CancellationToken; перед каждой операцией после окончания ввода создаётся CancellationTokenSource с CancelAfter(5 секунд). Ошибка отмены обрабатывается отдельно. Быстрые запросы обычно завершаются до отмены — это ожидаемо. Рабочие запросы не замедляются искусственно.

Проверка int/decimal использует TryParse. Параметры имеют явные SQL-типы; число с запятой или точкой принимается как цена. При отсутствии товаров или заказов выводится сообщение. Соединения и reader освобождаются через await using, команды — через using.

## Запуск и демонстрация

```powershell
dotnet run --project "ADD.NET/Лабораторные работы/ПР_06_Асинхронность/AdoNetPractice06.csproj"
```

Команда выполняется из корня репозитория. В локальном appsettings.json указан `(localdb)\CodexSqlPractice`, база coffee_shop, Windows-аутентификация. Для другого сервера измените JSON или переменную `ConnectionStrings__CoffeeShop`.

На исходной базе: 6 товаров, 3 клиента. Проверьте «Кап», отсутствующее название, порог 200 и 999999, клиентов 1 и 999999. Пунктом 5 измените доступность товара 1 с 1 на 0, затем верните 1. Для отсутствующего ID выводится «Товар не найден». Все изменения доступности действительно записываются в учебную базу.

## Письменные ответы

1. **Преимущество асинхронного ожидания:** вызывающий поток не блокируется на время поддерживаемого ввода-вывода. Сам SQL-запрос от этого не становится быстрее.
2. **ExecuteReaderAsync и ReadAsync:** первый выполняет запрос и получает reader, второй перемещает его к очередной строке, при необходимости ожидая данные.
3. **Task<int> и int:** Task<int> представляет ещё выполняющуюся или завершённую операцию с целочисленным результатом; await получает её int либо выбрасывает исключение.
4. **Параметры в асинхронных запросах:** асинхронность меняет ожидание, но не способ безопасной передачи значений. SQL-код и пользовательские данные по-прежнему нужно разделять.
5. **CancellationToken:** передаёт запрос отмены операции. Отмена зависит от поддержки и текущего состояния операции и не гарантирует мгновенную остановку на сервере.
