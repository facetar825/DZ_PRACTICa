## Реализация

| Пункт | Действие |
|---|---|
| 1 | LoadProducts загружает DataTable через SqlDataAdapter.Fill; LoadCatalog объединяет товары и категории в DataSet и создаёт DataRelation |
| 2 | Каталог из загруженных DataRow с Field<int/string/decimal/bool> |
| 3 | Доступные товары через DataTable.Select с price ASC |
| 4 | Все товары по price DESC |
| 5 | Товары выбранной категории через GetChildRows |
| 6 | Изменение выбранной цены в памяти, вывод старой цены и RowState |
| 7 | Новая загрузка DataTable с сервера и сравнение цены с локальной копией |
| 8 | Товары дороже 200 и количество доступных товаров, без SQL |
| 9 | Категории со связанными товарами |
| 10 | Дополнительное задание: количество товаров в каждой категории по DataRelation, сортировка по убыванию |

Только пункты 1 и 7 обращаются к SQL Server. Fill синхронный; при закрытом исходном соединении адаптер сам открывает его на время загрузки и закрывает после. Возвращаемые таблицы доступны после освобождения соединения. Ключи id задаются явно для поиска строк. Локальные правки не отправляются в базу: Update адаптера и команды записи не вызываются.

Пункт 7 сохраняет локальную изменённую копию и загружает отдельную свежую таблицу для сравнения. Пункт 1 заменяет весь локальный каталог, поэтому прежние несохранённые правки исчезают. При незагруженном каталоге, пустых таблицах, неверном ID и некорректной цене выводятся сообщения.

## Запуск и демонстрация

Из корня репозитория:

```powershell
dotnet run --project "ADD.NET/Лабораторные работы/ПР_08_DataTable_DataSet/AdoNetPractice08.csproj"
```

В appsettings.json указан `(localdb)\CodexSqlPractice`, база coffee_shop. Для другого сервера измените JSON или ConnectionStrings__CoffeeShop.

Сначала выполните пункт 1. На исходных данных загружаются 6 товаров и 2 категории. Пункт 10 показывает «Напитки: 4» и «Десерты: 2», пункт 8 — 5 доступных товаров. В пункте 6 задайте товару 1 цену 999: состояние станет Modified. Пунктом 7 проверьте тот же ID — локальная цена 999, цена базы 120, совпадение False. После повторной загрузки пунктом 1 в каталоге снова 120. При изменённых данных используйте фактическую исходную цену из своей базы.

## Письменные ответы

1. **DataTable и SqlDataReader:** DataTable хранит строки и схему в памяти с возможностью повторного доступа и редактирования. SqlDataReader читает результат последовательно при открытом соединении.
2. **SqlDataAdapter:** загружает результаты через Fill в DataTable/DataSet; при настроенных командах способен отправлять изменения через Update. В этой работе используется только загрузка.
3. **DataSet:** объединяет несколько таблиц, отношения и ограничения в памяти.
4. **DataRelation:** связывает родительские категории и дочерние товары по id/category_id, позволяет получать дочерние строки через GetChildRows.
5. **Почему база не изменилась:** изменена только локальная DataRow. Присваивание и RowState сами по себе ничего не отправляют SQL Server; метод Update не вызывался.
