# 07. Асинхронная работа с базой данных в ADO.NET

Источник: `Асинхронная работа с базой данных в ADO.NET.pdf`.

## Краткий конспект

Task представляет завершение операции, Task<T> — также её результат. async разрешает использовать await, а await ожидает завершения без блокирования вызывающего потока на время незавершённого ввода-вывода. Сам SQL от этого не становится быстрее.

Пять методов: OpenAsync — открыть соединение; ExecuteScalarAsync — получить одно значение; ExecuteNonQueryAsync — выполнить команду без набора строк; ExecuteReaderAsync — получить reader; ReadAsync — перейти к следующей строке. CancellationToken передаёт запрос отмены; отмена не гарантирует мгновенной остановки на сервере. .Result и .Wait блокируют поток. Последовательные await на одном соединении не являются параллелизмом.

## Вопросы из лекции

1. Зачем нужен асинхронный доступ к базе данных ?

2. Что делает await?

3. Чем OpenAsync() отличается от Open()?

4. Для чего используется ExecuteReaderAsync()?

5. Почему после ExecuteReaderAsync() часто используют ReadAsync()?

6. Что возвращает метод с типом Task\<int\>?

7. Делает ли асинхронный запрос выполнение SQL быстрее ?

8. Для чего нужен CancellationToken?

9. Почему нежелательно использовать .Result вместо await?

10. Чем асинхронность отличается от параллелизма ?

## Ответы по порядку

1. Чтобы не блокировать вызывающий поток во время ожидания поддерживаемых операций ввода-вывода.

2. Ожидает завершение awaitable-операции и получает результат или повторно выбрасывает её исключение.

3. Open блокирует до завершения; OpenAsync возвращает Task, ожидаемый через await.

4. Для асинхронного выполнения запроса с получением SqlDataReader.

5. Получение reader и последующее чтение строк — отдельные операции, каждая может потребовать ожидания данных.

6. Task<int> представляет операцию, после await результатом будет int.

7. Нет, асинхронность меняет способ ожидания, а не план и скорость выполнения SQL.

8. Для передачи запроса отмены от пользователя или тайм-аута к поддерживающей его операции.

9. Result блокирует поток, а в некоторых контекстах может способствовать взаимной блокировке.

10. Асинхронность организует ожидание без блокирования; параллелизм означает одновременное выполнение работ.

## Выполненная практическая часть

GetAvailableProductCountAsync возвращает количество доступных товаров. GetProductByIdAsync использует @id, ExecuteReaderAsync и ReadAsync. Оба вызываются из входной точки через await; токен отмены действует 5 секунд на всю последовательность. Отсутствие товара, ошибка SQL и отмена обрабатываются.
